# theDev 回報工具 — 掛載與設定說明

將此 **theDev** 資料夾整包複製到遊戲專案的 `src/` 底下，依下列方式掛載與設定即可讓該遊戲回報到同一份 Google Sheet（不同分頁）。

---

## 一、資料夾結構

```
src/
  theDev/
    core/           ← 工具本體（預設不改）
      TheDev.tsx
      TheDevContext.tsx
      apiClient.ts
      api.ts        ← 後端 API_BASE_URL 預設值
      types.ts
      theDev.scss
    configs/        ← 題目與預設選項（可改）
      defaultSelfTest.ts
    mappers/        ← 送後端的資料轉換（可改）
      mapToFeedback.ts
    index.ts
    使用說明.md     ← 本檔
```

- **core**：面板 UI、狀態、API 呼叫、API 網址預設值，預設不改。
- **configs**：自測題題目與選項，可在這裡新增或改寫。
- **mappers**：表單資料轉成後端 API 的 body，若要自訂欄位可改這裡。

---

## 二、掛載方式

在遊戲的根元件（例如 `App.tsx`）包一層 **TheDevProvider**，並在畫面中渲染 **TheDev** 元件。

### 1. 引入

```tsx
import { TheDevProvider, TheDev, API_BASE_URL } from "./theDev";  // 若複製到 src/theDev
// 或
import { TheDevProvider, TheDev, API_BASE_URL } from "@/theDev";  // 若專案有設定 @ 別名
```

### 2. 最小掛載範例

可從 theDev 匯入預設的 `API_BASE_URL`（定義在 `theDev/core/api.ts`），或用專案自己的網址傳入 `apiBaseUrl` 覆蓋：

```tsx
import { TheDevProvider, TheDev, API_BASE_URL } from "./theDev";

function App() {
  return (
    <TheDevProvider
      apiBaseUrl={API_BASE_URL}
      project="我的遊戲A"
      appVersion="0.0.1"
    >
      {/* 遊戲內容 */}
      <YourGame />
      <TheDev />
    </TheDevProvider>
  );
}
```

### 3. Provider 參數說明

| 參數 | 必填 | 說明 |
|------|------|------|
| **apiBaseUrl** | 是 | 後端 API 網址（例如 Vercel 部署網址），結尾不要加 `/`。 |
| **project** | 否 | 專案／遊戲名稱，對應同一份 Google Sheet 的**分頁名稱**；預設 `"theDev"`。不同遊戲請設不同值，例如 `"GameA"`、`"GameB"`。 |
| **appVersion** | 否 | 開發版本號，會帶入每筆回報；預設 `"0.0.0"`。 |
| **selfTestConfig** | 否 | 自測題題目與選項，不傳則使用 `configs/defaultSelfTest.ts`。見下方「自測題題目」。 |
| **snapshotPayload** | 否 | 快照紀錄模式要一併送出的數值物件，見下方「快照數值」。 |
| **token** | 否 | 若後端有啟用 `X-DEVLOG-TOKEN`，在此傳入。 |

同一份 Sheet 下，每個遊戲用 **project** 區分，後端會寫入對應分頁（需先在試算表裡手動新增該分頁名稱）。

---

## 三、自測題題目

自測題的題目與複選選項由 **SelfTestConfig** 提供，有兩種方式。

### 方式 A：使用預設並改寫 configs

複製 `configs/defaultSelfTest.ts` 為新檔（例如 `configs/myGameSelfTest.ts`），修改 `questions` 陣列：

```ts
import type { SelfTestConfig } from "../core/types";

export const myGameSelfTestConfig: SelfTestConfig = {
  questions: [
    {
      id: "q1",
      order: 1,
      title: "第一題標題",
      options: [
        { value: "opt1", label: "選項一" },
        { value: "opt2", label: "選項二" },
      ],
    },
    // 可多題
  ],
};
```

掛載時傳入：

```tsx
import { myGameSelfTestConfig } from "./theDev/configs/myGameSelfTest";

<TheDevProvider
  apiBaseUrl="..."
  project="我的遊戲A"
  selfTestConfig={myGameSelfTestConfig}
  appVersion="0.0.1"
>
  <TheDev />
</TheDevProvider>
```

### 方式 B：直接在掛載處傳入物件

```tsx
const myQuestions = {
  questions: [
    { id: "q1", order: 1, title: "題目一", options: [{ value: "a", label: "A" }, { value: "b", label: "B" }] },
  ],
};

<TheDevProvider
  apiBaseUrl="..."
  project="我的遊戲A"
  selfTestConfig={myQuestions}
  appVersion="0.0.1"
>
  <TheDev />
</TheDevProvider>
```

## 四、快照數值怎麼放入 API 回傳

「快照紀錄」模式會把**當下狀態**（關卡、血量、設定等）一併送出。這些數值由遊戲自己提供，透過 **snapshotPayload** 傳給 Provider。

### 1. 靜態快照（掛載時給定）

```tsx
<TheDevProvider
  apiBaseUrl="..."
  project="我的遊戲A"
  snapshotPayload={{ level: 1, difficulty: "normal" }}
  appVersion="0.0.1"
>
  <TheDev />
</TheDevProvider>
```

### 2. 動態快照（依遊戲狀態更新）

在遊戲元件中取得狀態後，用 **useTheDev** 的 **setSnapshotPayload** 更新，送出的回報就會帶上最新內容。

```tsx
import { useTheDev } from "./theDev";

function GameScreen() {
  const { setSnapshotPayload } = useTheDev();
  const [level, setLevel] = useState(1);
  const [hp, setHp] = useState(100);

  // 例如：進入關卡或定期更新快照
  useEffect(() => {
    setSnapshotPayload({ level, hp, updatedAt: new Date().toISOString() });
  }, [level, hp, setSnapshotPayload]);

  return (/* 遊戲畫面 */);
}
```

快照內容會出現在「快照紀錄」表單的「目前快照資料」區塊，並在送出時併入**回報內容**一併傳到後端（後端寫入同一份 Sheet 的對應分頁）。

## 五、後端 API 與 Google Sheet

- 後端需提供 **POST /api/feedback**，body 含：`專案`、`回報類型`、`回報區塊`、`回報內容`、`開發版本號`（回報時間可由後端補上）。
- **專案** 對應試算表內的**分頁名稱**；同一份 Sheet、不同遊戲用不同分頁即可。
- 若需自訂送出的欄位格式，可改寫 **mappers/mapToFeedback.ts**，再在 core 內依專案需求決定是否改用自訂 mapper。

---

## 六、複製到遊戲專案後的檢查清單

1. 已將 **theDev** 資料夾複製到遊戲的 `src/theDev`。
2. 根元件已用 **TheDevProvider** 包住，並渲染 **TheDev**。
3. **apiBaseUrl** 已設為實際後端網址（例如 `https://the-dev-one.vercel.app`）。
4. **project** 已設為該遊戲專案名（與 Sheet 分頁名稱一致）。
5. （選填）已設定 **selfTestConfig** 或沿用預設。
6. （選填）需要快照時，已設定 **snapshotPayload** 或在遊戲內用 **setSnapshotPayload** 更新。
7. Google 試算表內已新增該 **project** 名稱的分頁，且已共用給後端服務帳號。
